# AI Workflow Rules

## Approach

Build in small steps, phase by phase, following `docs/roadmap.md` (Bangla; the plan of record) and
these context files. `CLAUDE.md` is the map of the repo; `context/` holds the what (overview), the how
(architecture, code standards, UI) and the where-we-are (progress tracker). Implement against these. Don't
invent product behaviour.

## Session Start

1. Read `CLAUDE.md` (auto-loaded) and `context/progress-tracker.md`.
2. Read the other context files only when the task touches them: UI work → `ui-context.md`;
   new route/table/feature → `architecture.md` + `code-standards.md`.
3. Read only the code the task needs. Don't re-explore the repo.

## Scoping Rules

- One feature unit at a time; small, verifiable steps.
- Don't mix unrelated boundaries in one step (e.g. storefront checkout + POS register).

## When to Split Work

Split a step if it combines:
- A SQL migration and a large UI change (land the migration and its functions first)
- Online (`orders`) and offline (`pos_*`) money flows
- Behaviour that isn't defined in the roadmap or context files

If a change can't be checked end to end quickly, the scope is too broad. Split it.

## Handling Missing Requirements

- Don't invent product behaviour (prices, policies, statuses). Ask the user.
- If a requirement is unclear or missing, add it under **Open Questions** in `progress-tracker.md`.
- Seeded custom-jersey prices are placeholders; don't treat them as real.

## Ask Before (never do on your own)

- Applying any migration to the live DB (`node scripts/apply-sql.mjs`), and never with `--force`
- Running demo seed/remove against the live DB
- `npm run deploy`, commits, pushes
- Deleting test orders/payments/bills, or any step in the CLAUDE.md "Alpha → live checklist"

## Protected Files

Don't modify unless the user explicitly asks:
- `.next/`, `.open-next/`, `.wrangler/`, `node_modules/` (read Next docs only)
- `.env*` (never read or print secrets; use `.env.example` for key names)
- Migrations that are already applied (add a new migration instead)
- `components/ui/*` primitives: extend carefully, as many screens depend on them
- The `nextjs-agent-rules` block in `AGENTS.md` (it is regenerated by `next dev`)

## Keeping Docs in Sync

After a meaningful change, update:
- `context/progress-tracker.md`: always (completed / in progress / next / session notes)
- `CLAUDE.md`: when a new area, key file, or migration is added, or one is applied live
- `context/architecture.md`: new boundary, storage or auth decision, or invariant
- `context/code-standards.md` / `ui-context.md`: new convention or token
- `docs/roadmap.md`: phase status boxes (written in Bangla)

## Before Moving to the Next Unit

1. The unit works end to end within its scope
2. No invariant in `architecture.md` is broken (money on the server, stock through `stock_apply()`, cacheable public pages, audited writes)
3. New text exists in both `bn` and `en`; it looks right in light and dark mode
4. `npx tsc --noEmit` and `npm run lint` pass (`npm run build` for routing/config changes)
5. `progress-tracker.md` is updated
